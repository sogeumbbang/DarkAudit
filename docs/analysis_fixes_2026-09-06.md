## 판정 계약 v1.2

[인터페이스 계약](../ai/specs/rule_ai_contract.md), [판정 명세](../ai/specs/risk_spec.md), 입출력 스키마와 Golden fixture를 함께 갱신했다.

- DA-03·04·07·12·15 각각 `detected / not_detected / insufficient_evidence / not_supported`를 반환한다. 검사 상태와 실제 탐지/KEEP가 일치해야 한다.
- DA-03은 실제 수락/거절 동작과 근거 라벨을 연결한다. 후보 KEEP도 원래 후보의 선택지 근거를 검증한다. 경고 문단만을 거절 버튼으로 인정하지 않는다.
- DA-15는 동일 상품·기기·경로의 서로 다른 상태와 초기/최종 금액·단위를 요구한다. 이미 고지되거나 사용자 선택으로 설명된 증가를 숨긴 비용으로 확정하지 않는다. 금액과 이율은 숫자 크기로 구분하지 않는다.
- DA-07의 작은/저대비/접힌 주요 정보와 DA-15의 후반 비용 공개를 구분한다. DOM 모드와 이미지 모드의 허용 규칙을 별도 프롬프트로 관리한다.
- 증거 계약 재시도 후에도 유효하지 않은 규칙은 미완료로 남기고 다른 유효 판정을 보존한다. 재시도와 모든 좌표 검증 응답의 토큰 사용량을 합산한다.

## 실행한 검증

Python 3.12에서 AI **84개**, 백엔드 **73개** 테스트 통과. 지원되는 Node.js 24.15.0에서 프런트 테스트 **13개**, Chrome 데스크톱/모바일 core flow 및 접근성 테스트 **26개** 통과. ESLint, 타입 검사/프로덕션 빌드, 15개 YAML 규칙 검증도 통과했다. CI 파일을 추가했으며 원격 CI 실행 결과는 아니다.

실제 모델 API 결과를 대시보드에 주입해 데스크톱·모바일 화면을 검토했고, 이 결과 화면의 axe serious/critical 위반은 두 크기 모두 0건이었다. 어두운 배경 위 상태 배지는 읽을 수 있는 명시적 배경/글자색으로 조정했다.

변경한 프런트 파일의 Prettier 검사는 통과했다. 저장소 전체 `format:check`에는 이번 변경과 무관한 기존 4개 파일의 서식 문제가 남아 있다: `e2e/core-flow.spec.ts`, `src/layouts/AppLayout.tsx`, `src/pages/landing/LandingPage.tsx`, `src/pages/support/SupportPages.tsx`.

### 실제 모델 연결

저장소 샘플 5장을 임시 DB의 실제 업로드/분석 API에 전달했다. 업로드 → OpenAI → 판정 검증 → DB → dashboard 응답이 완료됐다. 모델 분석 시간은 약 **40.45초**, 스키마/증거 재시도 1회였다. DA-04 1건, DA-03 2건, DA-12 1건을 저장했다. 후보 위치 선택 3회가 모두 `set-of-mark+cv`로 검증됐으며 해당 400 오류는 발생하지 않았다.

DA-07은 관찰 범위 내 미탐지, DA-15는 사용자 선택/최초 고지 관련 증거 계약을 만족하지 못해 **근거 부족**으로 기록됐다. 로컬 OCR 미설치도 경고로 노출됐다. 따라서 전체 검사 상태는 `complete=false`다. 탐지 개수 증가를 정확도 향상 수치로 해석하지 않는다.

## 남은 외부 검증과 관찰 범위

Figma 토큰, BrowserStack 인증 정보, 실제 대상 Figma URL/APK가 없어 이 두 서비스의 실연동은 검증하지 못했다. 공식 형식 fixture 및 모의 수집기로 확인한 범위와 구분해야 한다. URL은 실제 Chrome DOM 추출과 모의 캡처의 API 저장 경로를 검증했으며 실제 외부 사이트의 스마트 탐색 도달률을 측정하지 않았다.

지원 범위는 15개 중 5개 규칙이다. 정지 화면만으로 최초 선택 이력이나 숨은 상호작용을 모두 확정할 수 없다. Figma 프레임/경로 한도, APK 안전한 동작과 화면/행동 예산, URL 탐색 정책 이후의 화면은 별도 검사가 필요하다. 모든 화면을 배치 처리해도 원거리 화면의 모든 조합을 비교하지는 않는다.

배포 판정에는 검수된 clean/risky 라벨과 네 입력의 같은 시나리오를 사용해 수집 도달률·규칙별 precision/recall·bbox IoU를 별도로 측정해야 한다. 이번 수정은 그 평가를 가로막던 확인된 코드 결함과 무근거 정상 표시를 해결한 것이다.
