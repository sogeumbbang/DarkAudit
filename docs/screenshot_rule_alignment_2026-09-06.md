# 스크린샷과 기존 규칙의 정합성 수정

## 목표와 수정 범위

스크린샷에서 기존 YAML 정의에 해당하는 사례를 검출하도록 현재 지원 규칙 DA-03·04·07·12·15의 이미지 판정 경로를 정리했다. Rule Base 원본은 바꾸지 않았다. 모델도 `gpt-5.4-mini`로 유지했다. 지원 규칙을 15개 전체로 확장한 변경은 아니다.

확인된 불일치와 수정:

- **DA-04:** YAML의 note는 가격 없는 동의·기본값도 포함하고 추가 비용은 필수 조건이 아니라고 명시한다. 그러나 이미지 프롬프트와 checks는 유료 옵션으로 좁혀져 있었다. 선택 개인정보·마케팅 동의, 재투자/이해 확인의 기본 긍정 답변, 상위 플랜 등 기존 4개 체크를 계약에 반영했다.
- **DA-03:** 실제 대안은 거절 버튼 외에 다른 플랜·가입유형일 수도 있다. 선택 항목을 필수처럼 표현하는 경우도 기존 규칙에 포함된다. `pair_kind`로 실제 대안과 선택/필수 표시 근거를 구분하며, 가상의 거절 버튼을 요구하지 않는다.
- **DA-07:** 확대하면 읽힌다는 이유만으로 주요 정보의 시각적 축소를 제외하지 않도록 했다. 혜택 대비 크기·대비와 정보의 중요성을 함께 검토한다.
- **DA-15:** 사용자 선택 옵션 금액과 별도의 필수 수수료를 구분하도록 했다. 수익률 하락과 비용 이율 상승을 다른 단위 역할로 검증한다.
- **개별 제외:** 한 항목이 증거 계약을 만족하지 못하면 그 항목만 재검증·제외한다. 같은 규칙의 다른 유효한 탐지를 유지하고, 제외 사유는 `rejected_evidence`에 기록한다. 기준 신뢰도는 낮추지 않았다.

출력 계약은 **v1.3**이다. 스키마, 프롬프트, 판정 명세, 테스트 fixture를 함께 갱신했다.

## 실제 이미지 검증

[테스트 화면 원본](../ai/tests/fixtures/screenshot_rule_cases.html)으로 위험/정상 변형 10개 시나리오(12장)를 렌더링했다. 모델에는 스크린샷만 전달하고, 정답 라벨과 DOM 정보는 전달하지 않았다. 각 시나리오당 실제 모델 호출 1회다.

| 사례 | 위험 변형 | 정상 변형 |
| --- | --- | --- |
| 가격 없는 선택 동의·재투자 | DA-04 3건 | 탐지 없음 |
| 신청/거절의 시각적 위계 | DA-03 1건 | 탐지 없음 |
| 작은 저대비 원금 손실 안내 | DA-07 1건 | 탐지 없음 |
| 혜택 상실·후회 압박 문구 | DA-12 1건 | 탐지 없음 |
| 후반 필수 수수료 추가 | DA-15 1건 | 첫 화면부터 총액·수수료 고지 시 탐지 없음 |

의도한 규칙의 Finding 7건이 반환됐다. 좌표까지 동일 규칙·화면·IoU ≥ 0.5로 엄격하게 평가하면 **6건 일치, 1건 불일치**다. DA-15의 내용은 맞지만 모델의 좁은 텍스트 bbox가 라벨의 전체 문단 영역에 충분히 겹치지 않았다. 이를 성공으로 바꿔 계산하거나 평가 임계값을 낮추지 않았다.

처음 3종의 6개 시나리오는 수정 전 커밋 `57ec857`에도 동일한 이미지로 실행했다. **이전/이후 모두 5개 요소를 검출했다.** 따라서 이번 비교만으로 실제 탐지 재현율이 상승했다고 주장할 수 없다. 단순 예제의 통과는 실제 사용자가 놓친 화면까지 해결했다는 증거가 아니다.

초기 fixture의 정상 위계 버튼에도 채움색 차이가 남아 있었고, 정상 위험 고지의 글씨도 혜택보다 작았다. 두 정상 변형에서 해당 시각 차이를 제거한 뒤 동일 이미지의 이전/이후 비교를 수행했다. 사용한 최종 입력 해시와 결과는 아래 근거에 보관했다.

## 평가 방식과 회귀 테스트

기존 `micro/per_rule`은 Flow 안에서 같은 규칙을 한 번 찾으면 성공으로 계산해 개별 요소 누락을 가릴 수 있다. 이를 유지하되 **`instance_detection`**을 추가했다. 규칙·화면·bbox로 일대일 매칭하며, 결과가 없는 사례의 정답 요소도 누락으로 집계한다. 기존의 '재현율 100%' 보고서는 모든 요소를 찾았다는 의미로 해석하면 안 된다.

Python AI **90개**, 백엔드 **74개** 테스트가 통과했다. 무료 동의의 기존 YAML 체크, 선택/필수 표시, 비용/수익률 방향, 같은 규칙의 유효한 항목 보존, 잘못된 화면에서 찾은 사례의 누락 집계를 회귀 테스트로 추가했다. DA-03 선택/필수 표시 및 비용 이율 상승의 검증은 계약 테스트이며, 위 실이미지 smoke 사례에는 포함되지 않는다.

```bash
python -m ai.evaluation.screenshot_smoke --output /tmp/darkaudit-smoke
# 실제 모델 호출 및 API 사용량 발생
python -m ai.evaluation.screenshot_smoke --output /tmp/darkaudit-smoke --live
python -m unittest discover -s ai/tests -v
python -m unittest discover -s backend/tests -v
```

근거: [결과 보고서](evidence/screenshot-rule-alignment-2026-09-06/report.json), [입력·라벨 해시](evidence/screenshot-rule-alignment-2026-09-06/manifest.json), [이전/이후 탐지와 telemetry](evidence/screenshot-rule-alignment-2026-09-06/predictions.json).

현재 확인한 것은 기존 규칙과 코드 계약의 불일치 해소 및 제한된 예제의 동작이다. 다양한 실제 화면의 누락률·오탐률과 모델 간 성능 차이는 아직 측정하지 않았다.
