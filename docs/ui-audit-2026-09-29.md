## 핵심 판단

현재 랜딩은 레퍼런스의 코랄 리본·대괄호·사각 버튼을 이미 닮았다. 문제는 유사한 장식의 부족이 아니라, 랜딩과 업무 화면을 연결하는 색상 역할과 타이포 위계가 약한 것이다. 다음은 시각 검토에 따른 디자인 판단이며 자동 검사 오류와 구분한다.

| 우선순위 | 관찰 | 개선 방향 |
| --- | --- | --- |
| 높음 | 랜딩은 차콜+코랄, 앱은 본문·선·선택 상태까지 남색 중심이다. 따뜻한 마감 배경과 차가운 앱 배경도 연결감이 약하다. | 본문·기본 선·바탕을 중립색으로 통일하고 코랄은 주요 행동, 남색은 선택/정보 등 제한된 역할에 배정한다. 위험·성공색은 의미를 유지한다. |
| 높음 | 리본은 제품 기능을 설명하지 않으며 오른쪽 바깥으로 크게 잘린다. 모바일에서는 제목 옆에 곡선 일부만 남는다. | 화면 영역 → 탐지 위치 → 검토 근거를 표현하는 제품 그래픽을 우선 검토한다. 리본을 유지한다면 크기·선 밀도·불투명도를 줄이고 독립된 여백에 배치한다. |
| 높음 | 본문·설명·라벨이 작은 크기와 유사한 색에 몰려 있어 넓은 화면에서도 읽는 밀도가 높다. | 본문 16–18px, 업무 설명 14–16px, 메타 12–13px을 출발점으로 재조정한다. 서체 역할을 분리하고 강조색 대신 크기·여백으로 위계를 만든다. |
| 높음 | 결과 화면의 녹색 목업은 글이 없는 반복 막대여서 실제 탐지 근거를 이해하기 어렵다. | 모의 데이터용 금융 화면에 실제 문구·선택 상태·추가 비용을 넣는다. 캡처된 고객 화면 자체에 색 보정을 적용하지 않는다. |
| 중간 | 새 진단에서 데모 카드 4개와 실제 입력 유형 4개가 연속되어 선택이 중복되어 보인다. | 실제 입력 흐름을 중심으로 두고 데모는 보조 진입점으로 정리한다. |
| 중간 | 모바일 대시보드의 표는 오른쪽 열이 초기 화면에서 보이지 않는다. 문서 가로 넘침이 없다는 자동 결과와 별개로 발견성 문제가 있다. | 모바일 목록 카드로 전환하거나 가로 스크롤 안내와 핵심 열 우선순위를 제공한다. |
| 중간 | 모바일 결과에서 고정 챗봇 버튼이 점검 항목 설명 위에 겹친다. 결과는 목록→미리보기→상세가 길게 이어진다. | 모바일 챗봇을 축소하고 선택 항목의 근거/상세 접근을 단축한다. |
| 중간 | 가이드의 둥근 카드, 랜딩의 직각 버튼, 챗봇의 캡슐 형태가 서로 다른 인상을 준다. | 카드·컨트롤·플로팅 요소별 radius 사용 규칙을 정한다. |

## Bitnomial 레퍼런스 조사

출처: [Awwwards 출품 페이지](https://www.awwwards.com/sites/bitnomial), [Bitnomial 원본](https://bitnomial.com/). Awwwards 자체 인터페이스의 Inter Tight와 출품 사이트 서체를 혼동하지 않았다. 브라우저에서 원본의 computed style과 폰트 로딩 상태를 직접 확인했다.

1440px 뷰포트 실측값이며 반응형 전체에 고정되는 수치는 아니다.

| 역할 | 서체 | 크기 / 굵기 | 행간 / 자간 |
| --- | --- | --- | --- |
| 히어로 H1 | PP Neue Machina Inktrap | 74px / 400 | 88.8px / normal |
| 상품 H2 | PP Neue Machina Inktrap | 63px / 400 | 81.9px / normal |
| 히어로 본문 | IBM Plex Sans | 18px / 400 | 28.8px / normal |
| 내비게이션 | IBM Plex Sans | 21px / 400 | 29.4px / normal |
| Sign In / Learn More 링크 | PP Neue Montreal Mono | 약 21px / 500 | 약 29.4px / 0.42px |

제목은 굵기보다 독특한 글자 형태와 크기로 존재감을 만든다. 본문은 읽기 쉬운 산세리프, 짧은 영문 행동/메타 정보는 모노스페이스로 구별한다. 제목의 자간은 normal이며 현재 DarkAudit의 -0.045em을 그대로 레퍼런스 특성으로 이해하면 안 된다.

첫 화면의 흰 바탕·거의 검은 본문·코랄 CTA와 리본이 색상 역할을 단순하게 만든다. 세로 그리드와 선형 리본도 연결된다. 현재 캡처에서 스크롤 진입 전 콘텐츠가 비어 보이는 구간이 있어 원본 전체 애니메이션이나 하단 레이아웃을 완전히 평가한 것으로 보지 않는다.

## DarkAudit 적용 제안

- Wanted Sans는 한글 제목, SUIT는 본문/입력으로 역할을 명확히 한다. 폰트를 늘리기 전에 이 둘의 크기·굵기·자간을 조정한다.
- 영문 섹션 코드·DA-04 같은 규칙 ID·좌표에는 모노스페이스를 제한적으로 검토한다. 한글 버튼 전체를 모노스페이스로 바꾸지는 않는다.
- 랜딩 제목 64–76px / 500 / 행간 1.2–1.3, 모바일 36–40px부터 비교한다. 현재 제목의 강한 음수 자간은 -0.02em 전후와 시각 비교한다.
- 섹션 제목 40–48px, 업무 페이지 제목 30–36px, 본문 16–18px, 라벨 12–13px으로 역할별 스케일을 만든다. 이는 제안값이며 실측값이 아니다.
- 중립 바탕 #FAFAF8, 표면 #FFFFFF, 본문 #222222, 보조 #626262, 선 #E2E2DF를 시안 출발점으로 삼는다. 코랄 #FF795C는 주요 CTA에 제한하고 각 조합의 대비를 재검증한다.
- 적용 순서: 색상 토큰 → 타이포 역할 → 히어로 그래픽 → 업무 화면 밀도 → 모바일 표/챗봇.

## 자동 검사 결과

- 16개 페이지/뷰포트 조합에서 문서 가로 넘침 없음.
- 14개 조합에서 axe 위반 없음. 이 결과는 접근성 전체 준수를 보증하지 않는다.
- 대시보드 두 뷰포트에서 동일한 serious `definition-list` 위반 1종 발견.
- `frontend/src/pages/dashboard/DashboardPage.tsx:48`의 dl 내부 그룹에 dt/dd와 함께 p가 있어 유효하지 않다. 설명을 dd 안에 넣거나 별도 dd로 구조화할 수 있다.
- 이번 작업은 검사·조사 보고서이며 UI 재설계와 위반 수정은 적용하지 않았다.

## 후속 UI 변경

사용자 요청에 따라 아래 변경을 적용했다. 위 진단 내용과 캡처는 변경 전 기록이다.

- 전역 팔레트를 웜 화이트·차콜·중립색 선으로 통일하고 코랄 강조와 의미별 상태 색상을 유지했다.
- 랜딩 제목 자간을 완화하고 본문을 확대했다. 영문 코드·번호는 시스템 모노스페이스로 구분했다.
- 리본을 유료 옵션 사전선택과 개선 근거를 설명하는 HTML/CSS 제품 예시로 교체했다.
- 새 진단의 입력 폼을 데모보다 먼저 배치했다.
- 모바일 대시보드는 상태·후보 수·날짜를 담은 목록 카드로 전환했다. dl 구조 오류도 수정했다.
- 모바일 챗봇 버튼을 48px 아이콘으로 축소하고 접근 가능한 이름은 유지했다.
- 카드 모서리 규칙을 통일하고, 랜딩 검토 기준 메뉴를 실제 가이드 페이지로 연결했다.
- 이미 작업 중이던 랜딩 섹션 삭제는 유지했다. 결과 화면의 녹색 모의 캡처 데이터는 이번 UI 변경 대상에서 제외했다.

확인: 빌드·ESLint 통과, 단위 테스트 48개 통과, 접근성 및 주요 흐름 E2E 38개 통과. 랜딩·대시보드·새 진단을 320/390/768/1440px에서 캡처하여 가로 넘침 없음을 확인했다. 변경 파일 Prettier 검사를 수행했다. 저장소 전체 format:check에는 이번 작업에서 수정하지 않은 70개 파일의 기존 포맷 문제가 남아 있다.
